## Задача 1. Сумма чисел

`split_ranges(n, workers)` покрывает весь диапазон `1..n` без пропусков
и пересечений. Размеры частей отличаются не более чем на единицу:
при `n=10, workers=3` это `(1,4)`, `(5,7)`, `(8,10)`.
При `n=10^10, workers=4` каждый исполнитель получает 2 500 000 000 чисел.
Передаются границы, полный список чисел в памяти не создаётся.

`sum_range()` прибавляет числа обычным циклом `for`. Формула `n*(n+1)//2`
используется только после остановки таймера для проверки полученного ответа.

| Подход | Выполнение и сбор результатов | Особенность |
| --- | --- | --- |
| threading | `Thread` для каждой части, запуск всех потоков, `join()`, `Queue` | Общая память; в CPython с GIL этот Python-цикл не исполняется одновременно на нескольких ядрах |
| multiprocessing | Контекст `spawn`, `Pool.starmap()`, суммирование частичных ответов | Отдельные интерпретаторы могут работать на разных ядрах; есть затраты на запуск и передачу данных |
| asyncio | Корутина для каждой части, `gather()`, блоки по 100000 чисел, `await sleep(0)` | Один цикл событий; корутины уступают управление, но вычисления не становятся многоядерными |

В варианте с потоками исключения также передаются через очередь: программа
не выдаёт неполную сумму за правильный результат. `spawn` требует защиты
точки входа, иначе импорт модуля дочерним процессом мог бы запустить CLI повторно.

### Методика

`perf_counter()` измеряет весь вызов `run()`: создание исполнителей,
вычисление, объединение результатов и завершение. Подходы запускаются
последовательно; при нескольких повторах порядок меняется.
Для CPU выполнен один повтор каждого подхода с четырьмя исполнителями.

Предыдущий опыт на `10^13` остановлен без завершённых проходов, его время
не включено в сравнение. Опыт 10 сентября на `10^10` включал сон Mac;
он заменён новым измерением 21 сентября. Исторические файлы сохранены локально.

## Задача 2. Парсинг и сохранение в БД

### Источники

| Сайт | Страницы | Сохраняемые данные |
| --- | --- | --- |
| [Books to Scrape](https://books.toscrape.com/) | A Light in the Attic, Tipping the Velvet, Soumission | HTML `title`, название книги из `.product_main h1` |
| [Quotes to Scrape](https://quotes.toscrape.com/) | Главная, `/page/2/`, `/page/3/` | HTML `title` |

Шесть адресов находятся в `task2/urls.txt`; для проверки одной страницы
используется `task2/one_url.txt`. HTML разбирает BeautifulSoup с `html.parser`.
Автор книги отсутствует в источнике, поэтому записывается `Not specified by source`.
Авторы цитат не считаются авторами импортированных книг.

### Три способа выполнения

| Программа | Исполнители | Загрузка | Запись в БД |
| --- | --- | --- | --- |
| `threading_parser.py` | `Thread` на пакет, `Queue`, `join()` | `requests` | Отдельная `Session` на страницу, `psycopg2` |
| `multiprocessing_parser.py` | `spawn`, `Pool.map(parse_batch, ...)` | `requests` | Подключения создаются в дочерних процессах |
| `async_parser.py` | Корутина на пакет, `gather()` | `aiohttp.ClientSession` | Отдельная `AsyncSession`, `asyncpg` |

Шесть URL распределяются по трём пакетам из двух URL. Пакеты выполняются
конкурентно, внутри пакета страницы обрабатываются последовательно.
Порядок результатов в терминале зависит от завершения запросов.

В async-варианте `await session.run_sync(save_record, data)` адаптирует
общую ORM-логику к асинхронному драйверу через greenlet, без отдельного потока.
Этот приём не делает произвольную блокирующую функцию асинхронной.
Разбор HTML синхронный и на большой странице может задерживать цикл событий.

### Транзакции и повторный импорт

`ParsedPage` хранит уникальный URL, HTML-заголовок, хост, время и необязательный
`book_id`. `save_record()` получает транзакционную advisory-блокировку PostgreSQL
по хешу URL и проверяет существующую запись. Исполнители не делят одну `Session`.

Первый книжный URL создаёт `Book` и связывает его с источником. Пользователь
импорта: `bookcrossing-parser@example.invalid`; пароль случайный, хранится хешем.
При повторе обновляются заголовок и время источника; существующая книга
не дублируется и не редактируется. `flush()` получает ID, `session.begin()`
фиксирует транзакцию при успешном выходе и откатывает её при исключении.
`ok=true` выводится после фиксации данных.

Для цитат `book_id=null`: сохраняется заголовок страницы, но книга не создаётся.
Парсер не добавляет `library_items` и заявки обмена: страница о книге не означает
наличие физического экземпляра у пользователя. Шесть URL проверяют требуемую
логику; отдельного требования массово заполнить базу в условии нет.

### Запросы и ошибки

Допускаются HTTP(S)-адреса без встроенных учётных данных. Требуются HTTP 200
и непустой `title`; редиректы отключены, ответ ограничен 2000000 байт.
TLS-проверка включена. `requests` использует таймаут соединения/чтения 20 секунд,
`aiohttp` общий таймаут 20 секунд. При медленной передаче их поведение различается.
Повторных попыток нет. CLI рассчитан на доверенный список URL.
При ошибке выводится `ok=false` с описанием, команда завершается ненулевым кодом.

## Анализ

В I/O-эксперименте минимальная медиана у asyncio: 3.604307 с.
Разница с threading около 0.193 с, или 5.1%. Разброс повторов больше этой разницы,
поэтому устойчивое преимущество asyncio этим опытом не доказано.

Медиана multiprocessing выше. На неё могут влиять запуск процессов,
передача результатов, сеть, удалённые серверы, БД и планировщик.
Их вклад отдельно не измерялся, поэтому всё отставание нельзя объяснить
только расходами на процессы.

Потоки удобны для перекрытия ожиданий с синхронными библиотеками; asyncio
требует неблокирующего I/O; процессы позволяют распараллелить Python-вычисления
на нескольких ядрах. Способ выполнения выбирается по характеру нагрузки.
Программы используют одинаковую полезную работу и общую логику сохранения.

Для буквального выполнения CPU-условия остаётся согласовать `10^10`
либо выполнить завершённый опыт на `10^13`.
