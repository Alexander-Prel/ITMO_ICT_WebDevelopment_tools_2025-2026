# ЛР1. Серверное приложение для буккросинга

## Назначение и технологии

Сервис позволяет зарегистрировать профиль, разместить свои экземпляры книг,
найти экземпляры других пользователей и согласовать обмен через заявки.

Использованы Python 3.12, FastAPI 0.115.0, SQLModel 0.0.21,
SQLAlchemy 2.0.35, PostgreSQL 16, Alembic 1.13.2, Pydantic 2.9.2,
Uvicorn 0.30.6, python-jose 3.3.0 и passlib с Argon2.
Зависимости зафиксированы в `Lr1/requirements.txt`.

## Архитектура

```text
HTTP-запрос
  -> роутер FastAPI + проверка входной схемы Pydantic
  -> Depends: сессия БД, при необходимости текущий пользователь
  -> сервис: проверки прав и допустимости операции
  -> SQLModel / SQLAlchemy -> PostgreSQL
  -> выходная схема Pydantic -> JSON
```

Роутеры не содержат основной бизнес-логики. Сервисы принимают сессию и
проверенного пользователя, выполняют изменения и фиксируют транзакцию.
`response_model` определяет состав ответа и исключает хеш пароля.

## Модель данных

| Таблица | Основные данные |
| --- | --- |
| `users` | Имя, фамилия, уникальный email, город, контакты, описание, хеш пароля, дата регистрации |
| `books` | Название, автор, уникальный необязательный ISBN, описание, создатель, дата |
| `genres` | Уникальное название жанра и описание |
| `book_genre_links` | Составной первичный ключ из книги и жанра |
| `library_items` | Владелец, книга, состояние, статус доступности, комментарий, дата |
| `exchange_requests` | Автор заявки, запрошенный экземпляр, сообщение, статус и даты |

`User -> Book`, `User -> LibraryItem`, `Book -> LibraryItem` и
`LibraryItem -> ExchangeRequest` являются связями one-to-many.
`Book <-> Genre` является many-to-many через `BookGenreLink`.
Пользователи связаны с книгами через ассоциативную сущность `LibraryItem`:
она хранит не только внешние ключи, но и `condition`, `status`, `comment`, `added_at`.
Одна карточка книги может иметь несколько физических экземпляров.

Кроме шести предметных таблиц сохранена вспомогательная `parsed_pages`
(URL, заголовок страницы, источник, необязательная книга, время загрузки).
Она нужна для совместимости истории схемы с дальнейшим развитием проекта;
парсер и программы ЛР2 в состав этой сдачи не входят.
Таблица `alembic_version` хранит технический номер миграции.

Полные модели приведены в разделе [Модели данных](models.md).

## Все эндпоинты

Обозначения доступа: публичный, JWT, создатель карточки, владелец экземпляра,
участник заявки (автор либо владелец запрошенного экземпляра).
Проверка владения выполняется поверх проверки JWT.

| Метод | Путь | Назначение и доступ |
| --- | --- | --- |
| GET | `/` | Состояние API; публичный |
| POST | `/auth/register` | Регистрация, токен и профиль; публичный |
| POST | `/auth/login` | Вход по JSON с email и паролем; публичный |
| POST | `/auth/change-password` | Смена пароля с проверкой старого; JWT |
| GET | `/users/` | Список профилей; публичный |
| GET | `/users/me` | Текущий профиль; JWT |
| PATCH | `/users/me` | Изменение своего профиля; JWT |
| DELETE | `/users/me` | Удаление своего профиля без связанных данных; JWT |
| GET | `/users/{user_id}` | Профиль с вложенными объектами; публичный |
| POST | `/books/` | Создание карточки; JWT |
| GET | `/books/` | Каталог, поиск по `q`; публичный |
| GET | `/books/{book_id}` | Карточка с создателем, жанрами и экземплярами; публичный |
| PATCH | `/books/{book_id}` | Изменение карточки; создатель |
| DELETE | `/books/{book_id}` | Удаление карточки без экземпляров; создатель |
| POST | `/books/{book_id}/genres/{genre_id}` | Добавление связи с жанром; создатель |
| DELETE | `/books/{book_id}/genres/{genre_id}` | Удаление связи с жанром; создатель |
| POST | `/genres/` | Создание жанра; публичный |
| GET | `/genres/` | Список жанров; публичный |
| GET | `/genres/{genre_id}` | Жанр с книгами; публичный |
| PATCH | `/genres/{genre_id}` | Изменение жанра; публичный |
| DELETE | `/genres/{genre_id}` | Удаление жанра; публичный |
| POST | `/library-items/` | Добавление экземпляра в свою библиотеку; JWT |
| GET | `/library-items/` | Общий список экземпляров; публичный |
| GET | `/library-items/me` | Своя библиотека; JWT |
| GET | `/library-items/search` | Поиск чужих экземпляров; JWT |
| GET | `/library-items/{item_id}` | Экземпляр с книгой и владельцем; публичный |
| PATCH | `/library-items/{item_id}` | Состояние, статус и комментарий; владелец |
| DELETE | `/library-items/{item_id}` | Удаление экземпляра без заявок; владелец |
| POST | `/exchange-requests/` | Заявка на доступный чужой экземпляр; JWT |
| GET | `/exchange-requests/` | Все заявки с участием текущего пользователя; JWT |
| GET | `/exchange-requests/me` | Исходящие заявки; JWT |
| GET | `/exchange-requests/incoming` | Входящие заявки; JWT |
| GET | `/exchange-requests/{request_id}` | Подробная заявка; участник |
| PATCH | `/exchange-requests/{request_id}/accept` | Принятие ожидающей заявки; владелец |
| PATCH | `/exchange-requests/{request_id}/decline` | Отклонение ожидающей заявки; владелец |
| PATCH | `/exchange-requests/{request_id}/cancel` | Отмена ожидающей заявки; автор |

`q` означает строку запроса: поиск подстроки названия или автора без учёта
регистра. Для поиска чужих экземпляров также доступны `city`,
`available_only` (по умолчанию `true`), `limit` и `offset`.
Город сравнивается по подстроке без учёта регистра, пробелы по краям
поисковых значений отбрасываются. Собственные экземпляры исключаются
независимо от фильтра доступности.

Полные сигнатуры, параметры, типы и `response_model` приведены в
[коде эндпоинтов](api.md) и [схемах API](schemas.md).

## Авторизация

Регистрация и вход реализованы вручную в сервисе авторизации.
Библиотеки используются для Argon2 и подписи JWT, но не для готовой
системы управления пользователями. Уникальность email проверяется сервисом
и ограничением БД. В БД сохраняется хеш, а не исходный пароль.

JWT содержит `sub` с ID пользователя и `exp` со сроком действия.
`HTTPBearer` извлекает токен; зависимость проверяет подпись, срок действия
и существование пользователя. Идентификатор владельца/автора операции
берётся из токена, а не из отправленного клиентом JSON.
Подпись не шифрует содержимое JWT. Срок по умолчанию составляет 60 минут.
Смена пароля требует текущий пароль, но не отзывает уже выданные JWT.

## Управление обменом

| Действие | Заявка | Экземпляр |
| --- | --- | --- |
| Создание заявки | `pending` | Остаётся `available` |
| Принятие владельцем | `accepted` | `reserved` |
| Отклонение владельцем | `declined` | Не изменяется |
| Отмена автором | `cancelled` | Не изменяется |

Дубликат ожидающей заявки одного читателя на тот же экземпляр запрещён.
При принятии строка экземпляра блокируется через `FOR UPDATE`, состояние
перечитывается, другие ожидающие заявки на эту копию отклоняются.
Все изменения фиксируются одним `commit`, поэтому экземпляр не должен
быть одновременно обещан разным читателям через API.

Принятую заявку нельзя повторно принять или отменить через `cancel`.
Экземпляр с принятой заявкой нельзя вернуть в `available` через PATCH.
Удаление экземпляра с заявками запрещено для сохранения истории.

Владелец может вручную отметить экземпляр `exchanged`, но это не переносит
его в библиотеку читателя и не является двусторонним подтверждением передачи.
Принятие заявки в рамках этой работы означает согласование и резервирование.

## Миграции и время

1. `0001_initial`: исходная схема буккросинга и enum-типы.
2. `0002_parsed_pages`: вспомогательная таблица источников.
3. `0003_user_last_name`: фамилия пользователя.
4. `0004_timezone_aware_dates`: даты с часовым поясом.

Время создаётся в UTC; поля PostgreSQL используют `timestamp with time zone`.
Ответы API преобразуются в `Europe/Moscow` и содержат `+03:00`.
Миграция старых дат явно трактует прежние значения как UTC, сохраняя момент
события. Код подключения и всех миграций приведён в [отдельном разделе](database.md).

## Результат и границы реализации

Реализованы CRUD профилей, книг, жанров и экземпляров, а для заявок:
создание, чтение и отдельные действия изменения статуса. У заявок нет
универсального PATCH или DELETE: история сохраняется.
Три практики оформлены [отдельными папками](practices.md).

Разделение слоёв, типизация, вложенные ответы, PostgreSQL, миграции и ручная
JWT-аутентификация представлены в финальном коде. Отчёт собирается MkDocs.
Это учебный API без пользовательского фронтенда, административных ролей,
отзыва токенов и проверки владения почтой. Справочник жанров доступен для
изменения без авторизации. Для публичной эксплуатации эти ограничения
потребуют отдельной доработки.
