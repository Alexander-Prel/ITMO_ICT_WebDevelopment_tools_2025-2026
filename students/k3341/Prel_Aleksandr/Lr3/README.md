# Лабораторная работа 3

Прель Александр, K3341. Docker, HTTP-парсер и очередь Celery + Redis.

ЛР3 продолжает приложение для буккросинга из `Lr1` и использует HTML-разбор
и сохранение данных из `Lr2`. Все три папки должны находиться рядом.
Основной API, HTTP-парсер, PostgreSQL, Redis и Celery worker запускаются
в отдельных контейнерах; миграции выполняет одноразовый сервис `migrate`.

[Отчёт](../reports/docs/lab3.md). Исходники ЛР3 находятся в `lab3/`.

## Установка и запуск

Нужны работающий Docker Engine, Docker Compose v2 и Python 3 для генерации
локальных секретов. Python-зависимости приложения устанавливаются при сборке
образов; локальное виртуальное окружение для запуска контейнеров не требуется.

Из личной папки `students/k3341/Prel_Aleksandr`:

```bash
cd Lr3
bash setup.sh
bash compose.sh config --quiet
bash compose.sh up --build --wait --wait-timeout 180 -d
bash compose.sh ps -a
```

`setup.sh` создаёт `Lr3/.env` со случайным паролем PostgreSQL и ключом JWT.
Существующий файл сохраняется; секреты не выводятся. Шаблон полей:
`.env.example`. Реальный `.env` не коммитится и не попадает в Docker build context.
В macOS `compose.sh` также находит Docker CLI внутри Docker Desktop.
В Windows команды можно выполнять в WSL с интеграцией Docker Desktop.

Первый запуск скачивает образы и зависимости. Пять долгоживущих сервисов
должны стать `healthy`; у `migrate` ожидается `Exited (0)`.
Образы запускаются от непривилегированного `appuser`.

| Сервис | Адрес с компьютера |
| --- | --- |
| Основной Swagger | http://127.0.0.1:8003/docs |
| Swagger HTTP-парсера | http://127.0.0.1:8004/docs |
| PostgreSQL | 127.0.0.1:5433, база `bookcrossing_lab3`, пользователь `bookcrossing` |
| Redis | Порт на компьютере не публикуется |

Пароль для DataGrip находится в локальном `.env`. Эта БД независима от
локальной базы ЛР1. Docker volume сохраняет данные между остановками.
Для изменения внешних портов используй `API_PORT`, `PARSER_PORT`, `POSTGRES_PORT`
в `.env`. Внутри сети сервисы обращаются по именам `db`, `parser`, `redis`.

Compose-проект по умолчанию называется `bookcrossing-lab3-submission`.
Контекст сборки находится в родительской личной папке. `.dockerignore`
передаёт только нужные исходники `Lr1/Lr2/Lr3` и зависимости, исключая базы,
окружения, тесты, документацию и секреты.

## Синхронный импорт

1. Открой основной Swagger на порту 8003.
2. Зарегистрируй пользователя через `POST /auth/register` или войди через
   `POST /auth/login`. Аккаунты из отдельной базы ЛР1 здесь не существуют.
3. Скопируй `access_token`, нажми Authorize и вставь токен.
4. Вызови `POST /parser/parse`:

```json
{
  "url": "https://books.toscrape.com/catalogue/a-light-in-the-attic_1000/index.html"
}
```

Основной API отправляет HTTP-запрос сервису `parser`, получает извлечённые
поля и сохраняет источник и книгу в PostgreSQL. Ответ приходит после commit
и содержит `ok`, `title`, `page_id`, `book_id`. Сам HTTP-парсер не имеет БД.

Повтори этот URL: идентификаторы источника и книги останутся прежними.
`GET /parser/pages` показывает сохранённые источники, `GET /books/` книги.
Значения ID зависят от содержимого базы.

## Фоновый импорт

1. Передай тот же JSON в `POST /parser/parse/async`.
2. Ответ `202` содержит `task_id` и `PENDING`.
3. Используй `GET /parser/tasks/{task_id}` для проверки состояния.
4. После `SUCCESS` поле `result` содержит сохранённые ID. При `FAILURE`
   поле `error` объясняет сбой.

`202` означает принятие задачи, а не готовность результата. Worker получает
задачу через Redis, вызывает HTTP-парсер и сохраняет данные той же функцией.
Неизвестный или истёкший ID даёт 404, неверный формат UUID даёт 422.

Для показа очереди из папки `Lr3`:

```bash
bash compose.sh stop worker
```

Поставь задачу, проверь `PENDING` и доступность `GET /books/`. Затем:

```bash
bash compose.sh start worker
```

Повтори запрос статуса: после обработки ожидается `SUCCESS`.
Для страницы `https://quotes.toscrape.com/` сохраняется источник,
но `book_id=null`. Физические экземпляры `library_items` не создаются.

## Проверка в PostgreSQL

```sql
SELECT p.id, p.url, p.title, p.book_id, b.title AS book_title,
       p.fetched_at AT TIME ZONE 'Europe/Moscow' AS fetched_at_msk
FROM public.parsed_pages AS p
LEFT JOIN public.books AS b ON b.id = p.book_id
ORDER BY p.id;
```

Повторная загрузка обновляет время источника, сохраняя связь с книгой.
При ошибке страницы транзакция откатывается; пустой успешный импорт не создаётся.

## Управление

```bash
bash compose.sh logs --tail=80 migrate api parser worker
bash compose.sh stop
bash compose.sh start
```

`stop` останавливает сервисы, `start` запускает уже созданные контейнеры.
После изменений кода нужен `up --build -d`. Для удаления контейнеров и сети
используется `down`; без `-v` тома сохраняются. `down -v` удаляет данные БД
и Redis и не нужен для обычной остановки.

Не меняй пароль `.env` у уже созданного PostgreSQL volume без отдельной смены
пароля в базе: переменная инициализирует пользователя только при первом запуске.
При занятом внешнем порте измени соответствующий параметр в `.env`.
