Прель Александр, группа K3341.

Профили пользователей, каталог книг и жанров, личные библиотеки, поиск чужих
экземпляров, создание и обработка заявок на обмен. Интерфейс API: Swagger UI.

[Задание](https://rendex85.github.io/WebDevelopmentLabsDocs/lr2/lr2/)

## Окружение

Python 3.10+ (проверено на 3.12), PostgreSQL (проверено на 16), Git.
DataGrip и PyCharm необязательны: это клиенты для работы с БД и исходниками.
Сервер PostgreSQL устанавливается и запускается отдельно.

Все следующие команды выполняются из папки `Lr1`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

В Windows активация: `.venv\Scripts\Activate.ps1` (PowerShell).

В административном подключении `psql` создать отдельную роль и пустую БД:

```sql
CREATE ROLE bookcrossing LOGIN;
\password bookcrossing
CREATE DATABASE bookcrossing_db OWNER bookcrossing;
```

`\password` запрашивает новый пароль интерактивно. В DataGrip вместо этой
команды пароль роли задаётся в настройках роли администратором БД.
Создание роли и базы выполняется один раз, не при каждом запуске API.

Создать локальный `.env` по `.env.example`. Указать свой пароль в `DB_URL`
и длинный случайный `SECRET_KEY`. Ключ можно получить командой:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Специальные символы в пароле внутри URL необходимо URL-кодировать.
В репозитории нет готового пароля БД или ключа подписи токенов.
Без переменных `DB_URL` и `SECRET_KEY` приложение не запускается.

```bash
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

- Swagger UI: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).
- OpenAPI: [http://127.0.0.1:8000/openapi.json](http://127.0.0.1:8000/openapi.json).
- Остановка сервера: Ctrl+C в терминале запуска.

Если порт занят, выбрать другой, например `--port 8002`.
Для разработки можно добавить `--reload`.

## Структура

| Путь | Назначение |
| --- | --- |
| `app/main.py` | Приложение и подключение роутеров |
| `app/api/routes/` | HTTP-обработчики |
| `app/schemas/` | Входные и выходные модели Pydantic |
| `app/services/` | Проверки прав и бизнес-логика |
| `app/models.py` | Таблицы и связи SQLModel |
| `app/db/session.py` | Движок и сессия PostgreSQL |
| `app/core/` | Настройки, JWT, хеширование и время |
| `migrations/` | Версии схемы Alembic |
| `practices/` | Отдельные точки входа трёх практик |

Основная модель буккросинга состоит из шести таблиц. Дополнительная
`parsed_pages` сохранена вместе с миграцией `0002` для совместимости истории
схемы с развитием проекта. Парсер и задания ЛР2 в эту сдачу не входят.
`alembic_version` является служебной таблицей Alembic.

## Практики

Практики 1.2 и 1.3 используют общий код предметной области из `app/` и
фабрику `practices/database_app.py`, но отдельные схемы PostgreSQL.
Запускать команды по одной либо в разных терминалах:

```bash
python -m uvicorn practices.practice_1_1.main:app --port 8011
python -m uvicorn practices.practice_1_2.main:app --port 8012
python -m uvicorn practices.practice_1_3.main:app --port 8013
```

У каждой практики Swagger находится по пути `/docs` на её порту.
Практика 1.1 хранит данные в памяти, 1.2 создаёт таблицы через `create_all`,
1.3 применяет миграции. Для схем 1.2 и 1.3 роль должна иметь право `CREATE`
в базе (оно есть у владельца базы). В основном приложении схема обновляется
только явно запущенными миграциями. `downgrade base` удаляет таблицы: не
использовать эту команду в базе с нужными данными.

## Авторизация и ограничения

Регистрация и вход принимают JSON и возвращают `access_token`.
В Swagger в поле Authorize вставляется только значение токена: префикс
Bearer добавляется интерфейсом. При смене пользователя сначала Logout,
затем новый токен; текущий профиль проверяется через `GET /users/me`.

Принятая заявка резервирует экземпляр (`accepted` + `reserved`), но не
переносит его к новому владельцу. Ожидающие конкурирующие заявки отклоняются.
Физическая передача и её двустороннее подтверждение не реализованы.
Пароли хешируются Argon2; существующие JWT не отзываются при смене пароля.
Учебная версия не содержит отдельного фронтенда, ролей администратора,
проверки владения email и строгой политики сложности паролей.
