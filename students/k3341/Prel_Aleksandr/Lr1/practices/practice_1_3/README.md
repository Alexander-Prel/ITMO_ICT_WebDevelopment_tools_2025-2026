# Практика 1.3. Миграции и структура приложения

[Задание](https://rendex85.github.io/WebDevelopmentLabsDocs/lr2/pr3/).

Отдельная точка входа `main.py` запускает фабрику `../database_app.py`
с применением Alembic-миграций в схеме `practice_1_3`.
При старте фабрика передаёт своё соединение в Alembic, поэтому миграции
не изменяют основную схему `public`.

Настройки читаются из корневого `.env` через `app/core/config.py`.
Код разделён на роутеры, сервисы, модели и схемы. Секреты исключены из Git.
История миграций находится в `migrations/versions/`, её последняя версия:
`0004_timezone_aware_dates`. `upgrade` применяет изменения,
`downgrade` выполняет обратные операции. Основное приложение также
использует миграции, но они запускаются отдельной командой до старта API.

После настройки PostgreSQL и `.env`, из корня `Lr1`:

```bash
python -m uvicorn practices.practice_1_3.main:app --port 8013
```

[Swagger UI](http://127.0.0.1:8013/docs).
Не выполнять откат с удалением таблиц в базе с нужными данными.
